# 项目规则与规范

## 1. 项目结构规范

### 1.1 目录结构

```
anime_role_detect/
├── src/               # 核心源代码
│   ├── backend/       # 后端服务
│   ├── core/          # 核心功能模块
│   ├── scripts/       # 脚本文件
│   ├── utils/         # 工具类
│   └── web/           # Web相关
├── tests/             # 测试代码
├── docs/              # 文档
├── data/              # 数据目录
└── scripts/           # 项目级脚本
```

### 1.2 命名规范

- **文件命名**：使用小写字母，单词间用下划线分隔（snake_case）
- **目录命名**：使用小写字母，单词间用下划线分隔（snake_case）
- **类命名**：使用驼峰命名法（CamelCase）
- **函数命名**：使用小写字母，单词间用下划线分隔（snake_case）
- **变量命名**：使用小写字母，单词间用下划线分隔（snake_case）
- **常量命名**：使用全大写字母，单词间用下划线分隔（SNAKE_CASE）

## 3. 代码检查规则

### 3.1 荣誉代码检查

**荣誉代码**定义：指重复创建的、不必要的对象或资源，导致内存泄漏或性能下降的代码。

**检查要点**：

1. **分类器实例**：检查是否重复创建分类器实例
2. **模型加载**：检查是否重复加载模型文件
3. **缓存管理**：检查缓存是否有大小限制
4. **资源释放**：检查文件、网络连接等资源是否正确释放

### 3.2 代码质量检查

1. **代码风格**：遵循PEP 8规范
2. **类型提示**：使用类型提示提高代码可读性
3. **注释规范**：关键函数和复杂逻辑需要添加注释
4. **测试覆盖**：确保核心功能有测试覆盖

### 3.3 安全检查

1. **输入验证**：所有用户输入需要验证
2. **路径遍历**：防止路径遍历攻击
3. **敏感信息**：不在代码中硬编码敏感信息
4. **依赖安全**：定期更新依赖包，避免安全漏洞

## 4. 性能优化指南

### 4.1 内存优化

1. **缓存管理**：使用LRU缓存策略，限制缓存大小
2. **对象复用**：避免频繁创建和销毁对象
3. **内存监控**：定期监控内存使用情况
4. **垃圾回收**：合理使用垃圾回收机制

### 4.2 计算优化

1. **批处理**：使用批处理减少计算次数
2. **并行计算**：利用多线程或多进程提高计算速度
3. **算法优化**：选择高效的算法和数据结构
4. **硬件加速**：利用GPU等硬件加速计算

### 4.3 I/O优化

1. **文件操作**：减少文件读写次数，使用缓冲
2. **网络请求**：使用连接池，减少连接建立开销
3. **数据库操作**：使用批量操作，减少数据库交互次数
